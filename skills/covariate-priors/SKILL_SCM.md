# SCM via PsN — method guidance (covariate-priors, SCM path)

The `scm_config` unit is draft and requires local review and approval.
Supply a site NONMEM/PsN provision and test the generated configuration
against the intended control stream and engine version.

Sources of truth (studied, not vendored — PsN is GPL; our configs are
generated fresh by `reference/scm_config.R`):
- https://github.com/UUPharmacometrics/PsN/blob/master/doc/ —
  config_template_standard.scm, config_template_backward.scm,
  config_all_default_parameterizations_explicitly.scm,
  config_centering_bivariate_covariate.scm,
  config_different_parameterizations_different_covariates.scm,
  config_emax_and_other_parameterizations.scm,
  config_grouping_categorical_covariate.scm,
  config_template_linearize.scm
- PsN scm user guide (https://uupharmacometrics.github.io/PsN/docs.html)

Applies when the MAP declares **SCM restricted to the prior list** as the
search method (skills/covariate-priors/SKILL.md). NONMEM/PsN engine path;
PsN is site-provided and shell-callable (D9).

## The one structural rule

**`[test_relations]` is the prior list, verbatim.** The config is
generated by `reference/scm_config.R` from the MAP's frozen prior list —
never hand-written at analysis time. A covariate absent from the list
cannot enter the search because it never reaches the config. The generated
config is itself a gate artifact (SME reviews it before scm runs).

## Precondition: the base model must be in `TV<PARAM>` form

**PsN's scm inserts covariate code around a typical-value variable named
`TV<PARAM>`.** A base model that computes the parameter in one expression —
`CL = EXP(THETA(1) + 0.75*LWT + ETA(1))` — gives scm nowhere to put the
relation, and it stops:

```
Could not determine a good place to add the covariate relation.
 i.e. No TVCL was found
 at /usr/local/bin/scm line 444.
```

Before declaring an SCM search, use a typical-value form for each
searched parameter. For example:
OFV does not move:

```
TVCL = EXP(THETA(1) + 0.75*LWT)
CL   = TVCL*EXP(ETA(1))
TVV  = EXP(THETA(2) + 1.0*LWT)
V    = TVV*EXP(ETA(2))
```

The generator requires typical-value assignments in `$PK`. Use
`extra_code` for additional per-pair parameterizations after that precondition
is satisfied.

`reference_scm_config()` and `reference_scm_config_backward()` take the
control stream as a required argument and REFUSE to emit a config unless, for
every searched parameter `P`, the `$PK` block both **assigns** `TVP` and
**uses** `TVP` in the assignment of `P`. A `TVCL` line that nothing consumes
is not a place scm can insert covariate code into. Both are literal string
checks on the parsed `$PK` lines — no arithmetic is interpreted — and the
parameter name must be a NONMEM identifier (`^[A-Za-z][A-Za-z0-9_]*$`). This
is caught at config generation rather than after a queue wait.

The assignment to `P` must have exactly the parameter name to the left of
the first `=`.

- `IF (COND) CL = TVCL*EXP(ETA(1))` — a **single-line conditional assignment**,
  a common NONMEM idiom — is **REFUSED**, because the text left of the `=` is
  `IF (COND) CL`, not `CL`. 
- The multi-line form satisfies the check, because the assignment sits on a line
  of its own:

  ```
  IF (COND) THEN
    CL = TVCL*EXP(ETA(1))
  ENDIF
  ```

The check is deliberately not being relaxed: it fails closed, it says exactly
what it wants, and rewriting the `$PK` block into the multi-line form is a
mechanical edit to the base model that leaves the fit identical. If a base model
genuinely cannot be written that way, that is an escalation to the SME, not a
reason to loosen the precondition.

**`nm_version=` is the site's `psn.conf` label, not a NONMEM version
number.** `nm_version=7` is refused by PsN at option parsing (`No NONMEM
version with name "7" defined in psn.conf`); on this site the labels are
`default` and `nm751`, listed by `psn -nm_versions`. The generator has no
default for it, and the analysis records the label it used in its
`run-config.yaml`.

## Config anatomy (order matters)

Single-line options must all come BEFORE the first `[bracket]` section —
PsN silently ignores single-line options placed after one (documented
trap).

| Option | House setting | Note |
|---|---|---|
| `model=` | base model file | must NOT already contain any test_relations combination |
| `search_direction=` | forward, then backward | two-step: see workflow |
| `p_forward=` | 0.05 | Declared for local review |
| `p_backward=` | 0.01 | idem |
| `continuous_covariates=` / `categorical_covariates=` | from prior list | |
| `missing_data_token=` | -99 | house missing convention; dataset should already be imputed+flagged per SKILL.md, the token is defense in depth |
| `do_not_drop=` | **every covariate on the prior list**, emitted automatically, plus any further name the caller passes | scm DROPs a covariate from `$INPUT` in every candidate that does not use it. Where the base model consumes one structurally (the fixed allometry `LWT = LOG(WT/1.30)`), the dropped candidate fails NMTRAN with `208 UNDEFINED VARIABLE`, and PsN records it `FAILED 999`, does not restart it, and **continues the search with exit status 0** — the candidate is lost silently (verified live, 2026-09-04). Reserved: setting it through `extra_options` is refused |
| `logit=` | any logit-transformed parameter (e.g. BIO) | scm adjusts parameterization |
| `parallel_states=` | 0 (default) | 1 tests all states simultaneously — declare in MAP if used |
| `nm_version` | the site `psn.conf` label (`psn -nm_versions`), recorded in the analysis `run-config.yaml` | required, no default; see the precondition section above |
| `threads`, `retries`, `tweak_inits`, `picky` | site/harness.yaml | operational, not method |

## Default parameterization states (the catalog)

From `config_all_default_parameterizations_explicitly.scm` — this is what
the state numbers in `[valid_states]` mean; the first valid state must
always be 1:

| State | Meaning | Code (continuous, centered on median) |
|---|---|---|
| 1 | none | `PARCOV=1` |
| 2 | linear | `1 + THETA(1)*(COV - median)` |
| 3 | piecewise (hockey-stick) | two slopes, split at median |
| 4 | exponential | `EXP(THETA(1)*(COV - median))` |
| 5 | power | `(COV/median)**THETA(1)` |

Categorical state 2: linear fractional shift per non-reference level, most
common level as reference (`IF(COV.EQ.1) PARCOV=1` ...).

Default bounds keep the factor positive (e.g. linear slope bounded by
`1/(median-maximum)` .. `1/(median-minimum)`); the generator emits them
with the code so nothing relies on PsN defaults silently.

**House `[valid_states]`** per the functional-form defaults in SKILL.md:
- continuous = `1,5` (none → power, the house default form). Linear (2) or
  exponential (4) only for pairs whose declared form departs — set
  per-pair via `[code]` redefinition (`V:WGT-5=exponential` style), not by
  widening the global state list.
- categorical = `1,2` (none → fractional change per level).
- States 3 and custom Emax states (7/8 pattern in the emax template) are
  available but each use is a per-pair MAP declaration.

## Workflow (forward then backward)

1. Generate the forward config from the prior list; review at the gate;
   run `scm config_forward.scm`.
2. From the forward result, generate the backward config:
   `[included_relations]` = the relations the forward step retained (with
   their state numbers), `[code]` pins any non-default parameterization
   each included relation used (e.g. `CL:AGE-2=power`), and
   `search_direction=backward`, `p_backward=0.01`.
3. The scm logfiles (`scmlog*.txt`) are the **verbatim search trail** the
   covariate gate requires — attached unedited, never transcribed.

## Advanced patterns (declare per-pair in the MAP before use)

- **Level grouping** (grouping template): same THETA across categorical
  levels via `[code]` — a declared pooling decision, with the clinical
  rationale on record.
- **Centered bivariate categorical** (centering template): population-mean
  preserving parameterization weighting by the level fraction — the
  fraction is data-derived, so this is generated after data access only as
  a declared choice.
- **Emax / sigmoidal states** (emax template): custom states with
  `[code]`, per-pair `[lower_bounds]`/`[upper_bounds]`/`[inits]` —
  bounds discipline is mandatory (Emax hill parameters unbounded is a
  known instability).
- **Linearized SCM** (linearize template): `linearize=1, foce=1,
  lst_file=` — NONMEM 7 only; large speedup for big models by searching
  on the linearized model. Whether the final model is re-run nonlinearly
  is part of the declaration.

## What the MAP must declare (SCM path)

1. The prior list (already frozen — SKILL.md predefinition gate).
2. p_forward / p_backward (house 0.05 / 0.01 unless tightened).
3. valid_states, and every per-pair form departure.
4. parallel_states if not 0; linearize if used (with the re-run policy).
5. do_not_drop set, missing token.
6. The backward step: always run, or forward-only with justification.

## Configuration defaults

1. **Forward + backward always.** Every SCM run is forward (0.05) then
   backward (0.01); the stricter backward pass prunes forward
   false-inclusions. Forward-only is a documented deviation.
2. **Linearized SCM allowed with nonlinear confirmation.** Permitted
   whenever runtime justifies it, provided the final model (retained
   relations) is re-estimated nonlinearly and that re-estimation is the
   reported result. Declared in the MAP.
3. **`parallel_states = 0`** (sequential, PsN default). States tried in
   valid_states order; with house states 1,5 the sequence is short.
4. **Categorical reference level: most common** (PsN default) —
   statistically stable, smallest SE on the fractional shifts. Reporting
   may restate effects against a clinical reference subject (forest
   stage).
