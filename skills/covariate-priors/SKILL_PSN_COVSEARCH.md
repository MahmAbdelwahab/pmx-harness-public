# PsN covariate-search family (beyond plain scm) — covariate-priors, PsN path

The `psn_covsearch` unit is draft. The five guarded entrypoints require
local approval before execution. Test command construction and result parsing
with the PsN version installed for the project and preserve the frozen prior
list. [PsN user guides](https://github.com/UUPharmacometrics/PsN/tree/master/doc)

Applies when the MAP declares a covariate search on the NONMEM/PsN engine
(`engine: nonmem`) and selects one of these methods over plain scm. The
default engine is nlmixr2 (config/engine.yaml); the NONMEM lane is a
per-analysis method decision, never an operational toggle.

## The one rule this lane inherits, unweakened

**The covariate search is restricted to the frozen prior list**
(skills/covariate-priors/SKILL.md — the predefinition gate, the
functional-form defaults). This document does not restate that rule; it
states how the restriction is ENFORCED for each tool. Every method here is
governed by it:

| Tool | How the prior-list restriction is enforced |
|---|---|
| scmplus | Consumes the scm config GENERATED by reference/scm_config.R; `[test_relations]` is the prior list verbatim. The reference REFUSES a config lacking the generator banner + `[test_relations]`. |
| boot_scm | Same generated config; same refusal. The search space per resample is the frozen list. |
| xv_scm | Same generated config; same refusal. The tool overrides direction/thresholds by design but the tested relations remain `[test_relations]`. |
| lasso | `relations` is the relation string GENERATED from the prior list; it is the search space and is a required, non-empty argument documented as generated — never hand-authored at analysis time. |
| frem | `-covariates` is the covariate set GENERATED from the prior list; there is no selection, so ALL listed covariates enter — none off-list can. |

None of these methods may add a covariate the prior list does not carry. A
generated config or generated relation/covariate list is the only admissible
input; a hand-authored one is refused (config tools) or is a governance
violation (lasso/frem) caught at the gate.

## Relationship to SKILL.md's three declared method paths

SKILL.md declares three per-analysis method paths. This lane realizes two of
them in the NONMEM/PsN idiom and adds stability tooling for the third:

- **SCM restricted to the prior list** → plain scm (SKILL_SCM.md), and its
  runtime/robustness variants here: scmplus (faster scm), boot_scm and
  xv_scm (post-selection stability / predictive validity). lasso is an
  alternative simultaneous selector (penalized, no stepwise multiplicity).
- **FREM** → frem here (full random effects; no selection).
- **Prior-anchored full model** → the frem full-model philosophy is its
  NONMEM/PsN counterpart when correlated covariates / missingness robustness
  are the driver (SKILL.md's stated "when it fits" for FREM).

The house significance levels (forward p=0.05, backward p=0.01) and the
retention criterion (statistical significance only; clinical relevance is a
reporting-stage narrative, not a filter) carry over from SKILL.md unchanged.

## The provision chain (one line, by reference)

    R reference_psn_*()  ->  tools/nonmem_container.sh <workdir> <psn-tool> <args>  ->  PsN 5.7.1 -> NONMEM 7.5.1 in container

Every PsN call goes through `tools/nonmem_container.sh <workdir> <tool>
<args>`, exactly as the estimation and uncertainty lanes do. The two
container preconditions (workdir inside a git repository so the git toplevel
mounts at its identical host path; external data added read-only via
`NONMEM_EXTRA_MOUNTS`) are stated in full in
skills/nonmem-estimation/SKILL.md and are NOT restated here.

## Operational vs. method settings (the governing split)

config/engine.yaml's three-layer governance is binding. For this family:

- **OPERATIONAL — read from config/engine.yaml `psn:` block, passed as
  `engine_config`:** `threads`, `retries`, `tweak_inits`, `picky`. The
  scm-config tools (scmplus, boot_scm, xv_scm) pass the full operational set
  through to their scm sub-runs; lasso and frem take the thread/retries
  subset. A change to any of these must not change a scientific result.
- **METHOD — MAP-declared per analysis, never in yaml, never defaulted by
  this skill:** the per-tool flags in the tables below (samples, groups,
  seed, t-value grid, relations, covariates, categorical handling, ...).

## The single-line-options-before-brackets trap (config tools only)

scmplus, boot_scm, and xv_scm are **config-file driven** and inherit the scm
trap: every single-line option must precede the first `[bracket]` section or
PsN silently ignores it (SKILL_SCM.md). Because the config is generated by
reference/scm_config.R, which emits all single-line options before
`[test_relations]`, the trap is already handled — provided the config is the
generated one (which the reference enforces). lasso and frem are
command-line driven; the trap does not arise for them.

## scmplus — first-class

**Purpose.** A drop-in wrapper around scm that reduces runtime via Adaptive
Scope Reduction: parameter-covariate relations that do not show promise in
early forward steps are stashed and not retested every step. **It runs the
house forward-then-backward workflow** — before the backward elimination
phase the stashed relations are re-tested (scmplus_userguide, verified
2026-08-31: "The basic scm algorithm proceeds in a Forward inclusion phase
and a Backward elimination phase" and stashed relations "are re-tested"
before backward). So scmplus RESPECTS house decision 1 (SKILL_SCM.md:
forward 0.05 then backward 0.01, always) with the same config, same
`[valid_states]`, same thresholds. **No open question on directionality** —
the inventory ambiguity resolved against the guide.

### Method-decision flags (MAP-declared)

| Flag | House default | Significance |
|---|---|---|
| (all scm config options) | from the generated config | p_forward/p_backward, valid_states, test_relations — the scm method surface, unchanged |
| `-scope_reduction_steps` | PsN default (after step 1) | when reduction applies ("all"/"none"/step) — a runtime knob; declare only if changed |
| `-retest_stashed_relations` | on | re-examine stashed relations before backward; keep on to preserve the backward pass integrity |
| `-p_cutoff` | PsN default | threshold for the scope-reduction decision |

Operational (from `engine_config`): full set via `.psn_operational_args`.

### Preconditions / gotchas

- **Cannot combine with `-linearize`** (scmplus does not support it). If the
  MAP declared linearized SCM (SKILL_SCM.md house decision 2), use scm, not
  scmplus.
- Requires SIGL with ADVAN 6/8/9/13 unless `-ignore_no_sigl`; warns on OMEGA
  blocks / IOV / eta-on-epsilon structures — check the base model first.

### Decisive artifact

`scmlog*.txt` — the verbatim forward/backward search trail (OFV, p-values,
retained relations per step), the covariate gate's required search trail
(SKILL.md deliverable 2), attached unedited, never transcribed.

## boot_scm — first-class

**Purpose.** Assesses the STABILITY of an scm covariate selection by running
scm on multiple bootstrap resamples and reporting the inclusion frequency of
each parameter-covariate relation across resamples. It is a stability
diagnostic AFTER selection, not a new selector.

### ⚠ The ID-renumbering corruption (same class as bootstrap; hard-stop)

boot_scm bootstraps the data, so it carries the **same ID-based IGNORE/ACCEPT
corruption** as the uncertainty-lane bootstrap: PsN renumbers individuals
during resampling, so an ID-based IGNORE/ACCEPT in the base model filters the
WRONG individuals after renumbering — silently. The reference reuses
`reference_psn_bootstrap_precheck` (skills/psn-uncertainty/reference/
psn_uncertainty.R) verbatim, running it on the base model named in the
config's `model=` line before any container call. A model needing ID-based
record selection must bake it into the analysis dataset before boot_scm.

### Method-decision flags (MAP-declared)

| Flag | House default | Significance |
|---|---|---|
| `-samples` | MAP-declared | number of bootstrap datasets; too few → noisy inclusion frequencies |
| `-seed` | **REQUIRED** | resampling reproducibility; the reference refuses without it |
| `-stratify_on` | MAP-declared | stratified resampling; no house default |
| `-methodA`/`-methodB` | methodB (PsN default) | nonlinear (A) vs. linearized-derivatives (B) resampling strategy |
| (all scm config options except `-base_ofv`) | from the generated config | the search per resample |

### Gotchas

- Known bug: boot_scm does not correctly build a dummy covariate from a
  time-varying covariate — enter time-varying covariates at baseline
  (already the SKILL.md default).

### Decisive artifact

`covariate_inclusion.csv` — 0/1 inclusion per relation per sample; column
means are the inclusion frequencies (the stability statistic). `bs_ids.csv`
records the resampled IDs.

## xv_scm — first-class

**Purpose.** Cross-validated scm: estimates on a training fold and predicts
on a held-out test fold to assess the PREDICTIVE validity of covariate
relations rather than in-sample fit. The decisive quantity is the prediction
OFV on held-out data.

### Method-decision flags (MAP-declared)

| Flag | House default | Significance |
|---|---|---|
| `-groups` | MAP-declared (PsN default 5) | number of CV folds |
| `-seed` | **REQUIRED** | fold-assignment reproducibility (stochastic) |
| `-splits` | 1 (PsN default) | repetitions with new data splits |
| `-stratify_on` | MAP-declared | preserves subgroup proportions across folds |

**Tool-forced settings (by design, not knobs):** xv_scm forces
`search_direction=forward`, `p_forward=1`, `gof=p_value`, and cannot take
`search_direction`/`gof`/`p_value`/`p_forward`/`p_backward`/
`update_derivatives`/`-base_ofv`/`-only_successful`. The generated config
still supplies `[test_relations]` (the prior list) and `[valid_states]`; the
tool overrides the direction/threshold lines. `-only_successful` is never
added (it interferes with the algorithm).

### Gotchas

- Produces many `split_X/` subdirectories and large disk usage; delete them
  post-run once the decisive CSVs are captured.

### Decisive artifacts

`xv_ofv_results.csv` (held-out prediction OFV — decisive),
`xv_relation_rank_order.csv`, `xv_percent_inclusion_by_level.csv`.

## lasso — first-class

**Purpose.** Simultaneous covariate selection and estimation via the LASSO
penalty, with the shrinkage tuning parameter (t-value) chosen by
cross-validation. Addresses the selection bias inherent in stepwise methods —
an alternative simultaneous selector to the scm family.

### Prior-list control (the relation string)

`relations` IS the search space and must be GENERATED from the frozen prior
list — the lasso analogue of `[test_relations]`, never hand-authored. Syntax
(lasso_userguide, verified 2026-08-31): `PAR:COV-type,COV-type,,PAR:...`,
colon after the parameter, comma between covariate-type pairs, double comma
between parameters, no spaces. Parameterization **type** codes: `1`
categorical, `2` linear continuous, `3` piecewise "hockey-stick" (optional
breakpoint as `COV-3-<bp>`).

**House caveat (a declared functional-form departure):** lasso offers only
linear / piecewise / categorical parameterizations — NOT the house continuous
default POWER form (SKILL.md functional-form defaults). Continuous effects
are multiplicative when `-log_scale` is on (the PsN default). Choosing lasso
therefore departs from the SKILL.md default form by construction; the MAP
must acknowledge this when it declares lasso.

### Method-decision flags (MAP-declared)

| Flag | House default | Significance |
|---|---|---|
| `-relations` | **REQUIRED**, generated from prior list | the search space |
| `-seed` | **REQUIRED** | CV fold-assignment reproducibility |
| `t_value` (fixed) / `-start_t`,`-stop_t`,`-step_t` | CV-selected over the grid | the shrinkage tuning parameter; the fixed-t flag spelling is **unverified — confirm at first real run** |
| `-groups` | 5 (PsN default) | CV folds |
| `-stratify_on` | MAP-declared | stratified fold assignment |
| `-log_scale` | on (PsN default) | multiplicative vs. additive covariate effects |

### ⚠ Final-model re-estimation (declare in MAP)

After CV selects the optimal t, lasso re-fits the regular model on the full
data with the covariate thetas FIXED from the lasso coefficients,
re-estimating the base PK parameters (lasso_userguide, verified 2026-08-31).
Whether that lasso final model is ACCEPTED as-is (coefficients retain LASSO
shrinkage bias) or the SELECTED relations are re-estimated UNPENALIZED in a
standard NONMEM model (removing the bias, the usual reporting choice) is a
method decision the **MAP must declare**.

### Gotchas

- Covariates must be standardized (mean 0, SD 1) before running.
- No `$PRIOR` support. Do not set `-min_retries` (conflicts with
  rounding-error handling).

### Decisive artifact

`lasso_coefficients.csv` — final coefficient per relation at the selected
t-value.

## frem — first-class

**Purpose.** Full Random Effects Modeling — **philosophically different**:
there is NO selection. ALL prior-list covariates enter simultaneously as
random effects and a full covariance between parameters and covariate effects
is estimated. This is the SKILL.md **"prior-anchored full model" alternative
path** (and SKILL.md's FREM row) realized in the NONMEM/PsN idiom — the fit
when covariates are correlated or missingness robustness matters, precisely
because there is no stepwise arbitration of collinearity.

### Prior-list control (the covariate set)

`-covariates` IS the full-model covariate set and must be GENERATED from the
frozen prior list. There is no `[test_relations]` because there is no search;
every listed covariate enters, so none off-list can. `covariates` is a
required, non-empty argument documented as generated.

### frem's own model-building steps (what the MAP declares)

frem runs an internal Model 1→4 sequence (optionally 5→6 with cholesky). The
decisions the MAP declares:

| Flag | Significance |
|---|---|
| `-categorical` | which covariates are non-ordered categorical → binary contrasts |
| `-log` | which covariates are log-transformed |
| `-skip_omegas` | OMEGA blocks excluded from the covariance estimation (e.g. IOV blocks) — a declared structural choice; with `-mu`, skipped omegas must already be ordered first |
| `-rescale` | rescale covariate ETAs to ~SD 1 in Model 2 (default on) |
| `-estimate_means` | estimate covariate means for missing-data handling (default on) |
| `-mu` | mu-modeling of covariate THETAs/ETAs |
| `-cholesky` | Models 5-6 Cholesky reparameterization (needs NONMEM ≥ 7.3) |

### ⚠ Preconditions (asserted at the gate against the control stream)

- The input model code must NOT already contain the listed covariates.
- No parameter named `FREMTYPE` in `$INPUT`/`$PK`/`$PRED`/`$ERROR`.
- Incompatible with `$MSFI` records; cholesky needs NONMEM ≥ 7.3.

### Decisive artifacts

`final_models/` Model 4 (the full-covariance FREM model). Pharmpy
post-processing writes `results.csv` / `results.json` / `results.html`
(covariate-effect estimates with CIs) — the reported covariate effects, and
the natural input to a forest plot (skills/forest-plots).

---

## mimp — available; declare per-analysis before use

Multiple Imputation of partially missing covariate data — cycles
base/regression/imputation/alternative models over `-imputations` rounds
(default 6). Used BEFORE scm/frem when covariate data is incomplete beyond
the SKILL.md median/mode imputation. Model roles (`base_model`, `reg_model`,
`mi_model`, `alt_models`, `chain_models`, `sim_model`) are all explicit; no
consolidated decisive artifact — imputations are combined manually. It does
NOT relax the SKILL.md missingness policy: the >10% missingness
sensitivity-analysis rule still governs. A reference entry point is authored
when an analysis declares mimp — not pre-built here.

## scmreport — available; declare per-analysis before use

Formatting-only utility downstream of scm/scmplus: extracts
inclusion/exclusion decisions and OFV changes from the scm log into a
presentable table. No methodological decisions. The verbatim `scmlog*.txt`
remains the gate's search-trail source of truth (SKILL.md deliverable 2);
scmreport is a convenience view, never a substitute for the raw log.

## What the MAP must declare (covariate-search lane)

1. The method: scmplus, boot_scm, xv_scm, lasso, or frem (with rationale
   tied to SKILL.md's "when it fits" for the chosen path).
2. scmplus: any scope-reduction knob change; confirmation that linearize is
   NOT needed (else use scm).
3. boot_scm: `-samples`, `-seed`, `-stratify_on` if used, methodA/B if not
   default; confirmation the base model has no ID-based IGNORE/ACCEPT.
4. xv_scm: `-groups`, `-seed`, `-splits`/`-stratify_on` if used.
5. lasso: the generated `-relations`, `-seed`, the t-value strategy
   (CV grid or fixed), `-groups`/`-stratify_on` if used, and the
   final-model re-estimation decision (penalized-as-is vs. unpenalized
   re-fit); acknowledgment of the linear/piecewise-only form departure.
6. frem: the generated `-covariates`, `-categorical`/`-log`/`-skip_omegas`
   as applicable, cholesky if used; confirmation of the FREMTYPE / no-MSFI /
   covariates-not-in-model preconditions.
7. In all cases: the frozen prior list is already predefined (SKILL.md
   predefinition gate) and the config/relations/covariates were GENERATED
   from it.

## House decisions inherited (not re-decided here)

1. Forward + backward always for the stepwise family (SKILL_SCM.md house
   decision 1) — scmplus honors it; boot_scm inherits the scm config's
   directions; xv_scm is forward-only BY TOOL DESIGN (a predictive-validity
   assessment, not a selection run) and is not a deviation from the policy.
2. Retention criterion: statistical significance only; clinical relevance is
   a reporting-stage narrative (SKILL.md), not a filter — unchanged for
   lasso/frem effect sizes.
3. Categorical reference level: most common (SKILL_SCM.md house decision 4).
4. Prior-list restriction is absolute (SKILL.md); enforced per tool as
   tabulated above.

## Reference implementation

`skills/covariate-priors/reference/psn_covsearch.R` — parameter-declared
wrappers, no hardcoded paths, operational flags read from a passed
`engine_config` list (parsed config/engine.yaml). It SOURCES
skills/psn-uncertainty/reference/psn_uncertainty.R (reusing `.psn_run`,
`.psn_locate`, `.psn_operational_args`, and `reference_psn_bootstrap_precheck`
verbatim) and skills/covariate-priors/reference/scm_config.R (chaining the
generated config), rather than restating them:

- `reference_psn_scmplus(workdir, config_file, engine_config, ...)` — refuses
  a non-generated config; runs the scm forward+backward workflow faster.
- `reference_psn_boot_scm(workdir, config_file, samples, seed, engine_config,
  ...)` — refuses a non-generated config; runs the ID-renumbering precheck on
  the config's base model first.
- `reference_psn_xv_scm(workdir, config_file, groups, seed, engine_config,
  ...)` — refuses a non-generated config; predictive-validity CV.
- `reference_psn_lasso(workdir, ctl_file, relations, seed, engine_config,
  t_value = NULL, ...)` — `relations` required, generated from the prior
  list; final-model re-estimation is a MAP decision.
- `reference_psn_frem(workdir, ctl_file, covariates, engine_config,
  categorical = NULL, ...)` — `covariates` required, generated from the prior
  list; no selection, all enter.

Each returns the built command vector, decisive-artifact paths, and a parser
stub whose column expectations are marked "unverified — confirm at first real
run".
